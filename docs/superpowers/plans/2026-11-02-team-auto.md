# Recorded Team Story Controller Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Automate the recorded positions and upgrades of the user's complete equipped team in observed Story stages.

**Architecture:** Keep Rukia route authorization intact and add a pure `src/team.lua` factory. Reuse native observations, serialized dispatch and terrain projection; add bounded role/max-level metadata and a scoped result observer. UI owns one active controller and auto-saves explicit team captures.

**Tech Stack:** Luau, existing Python bundler/checker, Roblox native observations; no new library.

**Spec:** `docs/superpowers/specs/2026-11-02-team-auto-design.md`

## Global Constraints

- Story only; up to 24 recorded placements; no new premium endpoints or coordinate generation.
- Eight-second exact feedback deadline; 1.5-second action spacing; same-run unresolved actions block rearming.
- Existing default reserve/run/time settings; replay and arming OFF on reload.
- Preserve source modules, local settings and unchanged loadstring. Missing data is not zero/success.

## Review Focus

- Incomplete or changed equipment: missing slots block arming; stale/unequipped records cannot act.
- Overlapping recorded positions: one model cannot satisfy two targets; ambiguous identity/position stops.
- Result/replay races: pending RPCs cannot overlap replay; stale/contradictory events cannot count wins.
- Settings or close while pending: stop without claiming cancellation of the native request; do not rearm that run.
- Partial capture persistence: merge only compatible contexts and save only plain data, never auto-arm.
